# Candidate and destination contract

Use existing task/source records rather than creating a separate cloud knowledge system. Record source location/hash, target task, stable method ID, evidence, conditions, action/output, completion evidence, failure conditions, current evidence status and the next actual artifact.

Method IDs remain stable when file names or entry layouts change. Candidates and references need concrete delivery locations; held/rejected items need reasons. Multiple methods can share an entry without duplication or contradictions. Unexplained important-source omissions require more reading or a narrower coverage claim.

The self-authored catalog and source fixture are not third-party examples. check_distillation.py --catalog <file> --lang en only reads records and checks hashes, unique IDs, declared task coverage and relative destination files. It does not assess source meaning, rights, exhaustive source coverage or method effectiveness, execute methods or authorize release.

Rollback conditions depend on the task: regression of previous successes, exceeded cost/latency budget, boundary misrouting, unauthorized disclosure or failure of confirmed requirements. Return the affected candidate and retain valid outputs.
